## 2. Access and resource protection actually checked

Production has a shared-password login with eight-hour signed sessions, Secure/HttpOnly/SameSite=Strict cookies, expiry/tamper checks and secret-rotation invalidation. Lock demo clears the cookie. Every UI asset, data API and CSV export is authenticated; `/healthz` exposes readiness only. Interactive API docs are disabled.

Exact host validation, HTTPS redirection behind the intended trusted ingress, same-origin POST enforcement, no cross-origin API allowance, CSP/frame protection, no-store cache policy, same-origin referrer policy and no-index headers are present. Original CSV/PDF/workbook/source paths are unavailable even to an authenticated viewer. Authorized viewers can still copy data legitimately displayed; this is access control, not DRM. Keep the GitHub repository private if case-distribution rules require it.

Resource controls: 120 HTTP requests/minute/IP, five login attempts/minute/IP and 20 total sign-in attempts/minute, 30 heavy requests/minute/session and 60 total/minute. One expensive calculation runs at a time, with immediate busy rejection rather than an unbounded queue. POST bodies are limited to 4096 bytes and five total seconds to receive. The 30-second HTTP calculation deadline reduces each solver phase to the remaining budget, with a 15-second per-phase maximum. Failure returns 503 rather than a partial/unproven recommendation. Rate limits return 429. A context deadline is checked at solver boundaries; this is not a claim to forcibly terminate arbitrary Python code at an exact millisecond.

A real-browser production test found that `Referrer-Policy: no-referrer` made browser form Origin opaque (`null`), causing correct sign-ins to fail. It was corrected to `same-origin`, retaining strict exact-origin validation rather than permitting null/cross-site requests. The final browser login and model requests pass. A negative container test also found Uvicorn could treat a middleware-construction configuration error as unsupported optional lifespan and continue listening with failures. Settings are now validated at module import and production explicitly requires lifespan startup; the final missing-secret container exits before serving requests.

The Docker entrypoint trusts forwarded headers because it is designed for Render's private ingress. Never expose that raw HTTP port directly to an untrusted public network. Aggregate budgets and single-calculation gating do not depend on a client being honest about its IP. The single shared password is not individual identities/MFA, and in-memory rate limits are not multi-instance infrastructure. Rotating either secret revokes all existing signed tickets; logout alone cannot revoke a previously stolen ticket elsewhere.
